# P4 運用整備: 同期維持・キャリブレーション・ドキュメント

**元資料**: `docs/design-v5-hybrid.md` §8(P4)、§3.4・§3.6・§6・§7
**用語**: 分からない用語は `docs/glossary.md` を参照

## ゴール

評価セットで正答率・正棄却率を提示でき、無人でも運用が回る状態にする。

## スコープ

### 1. AI Search同期の維持(§3.6)

- AI Searchは**31日間検索リクエストがないと**R2への定期同期ジョブが一時停止する(検索自体は継続。実害は「マニュアル更新が反映されない期間」の発生)
- EventBridge Scheduled Rule + 軽量Lambdaで**14日ごと**にダミー検索クエリを送信し、停止を確実に防ぐ

### 2. 閾値キャリブレーション(§3.4)

- 評価セット: **想定質問30問+回答不能質問10問**
- 検索スコア閾値θ1を評価セットでキャリブレーションする(固定値を信じない)
- F-01回帰テスト(LLMが一般知識で回答しないこと)を評価セットに含める(§6)。実行方法は下記「テスト」参照

### 3. README / ADR整備

- §2の比較検討プロセス(案A〜F)をADRとして残す(ポートフォリオの核、§7.1)
- 2クラウド運用の監視先(AWS CloudWatch / Cloudflareダッシュボード)と障害切り分け手順を明記(§6)

### 4. 運用手順書

- [ ] AI Searchインデックスエラーログの定期確認手順(**4MB超ファイルは通知なく索引されない**、§6。可能ならアラート化を検討)
- [ ] Anthropicコンソールのspend limit設定の確認手順(設定済み — env-setup-record §4)
- [ ] コスト監視: AWS Budgets(月¥1,000で80%通知、設定済み)+ Cloudflare側の課金開始監視(課金開始は30日前告知、§6)
- [ ] マニュアル更新の運用フロー(R2 `manuals/` へのアップロード→数分〜数十分で反映)

## テスト

- [ ] 評価セット(30問+10問)をリポジトリに含め、コマンド一発で再実行できるスクリプトにする(=回帰テスト化。マニュアル更新や閾値変更のたびに精度低下を検知できる)
- [ ] F-01回帰テスト: 一般知識で答えられるがマニュアルにない質問に対し、LLMの知識で回答**しない**ことを評価セットで確認
- [ ] EventBridge起動のダミークエリLambdaのユニットテスト(検索ポートのモックで配線を確認)

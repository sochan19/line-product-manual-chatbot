# P1 RAG MVP: マニュアル検索+出典付き回答

**元資料**: `docs/design-v5-hybrid.md` §8(P1)、§3.1・§3.4・§3.6・§4 / `docs/env-setup-record.md` §2・§7
**用語**: 分からない用語は `docs/glossary.md` を参照

## ゴール

マニュアルの質問に、出典付きで回答できる(F-01, F-02, F-06の実証)。

## 対応する必須要件

| ID | 要件 |
|---|---|
| F-01 | 回答の根拠はマニュアルのみ。LLMの学習知識・Web検索による回答を禁止 |
| F-02 | 回答時に出典を提示(ファイル名必須、見出しが取得できる場合はあわせて提示) |
| F-06 | マニュアル更新の自動反映(R2に置くだけで索引化 — AI Searchのマネージド機能で実現) |

## スコープ

1. **非同期処理の骨格完成**: webhook Lambda → SQS(+DLQ)→ worker Lambda(P0で未構築の場合)
   - 冪等性確保: `webhookEventId` をDynamoDBに条件付き書き込み、既存ならスキップ(§3.3)
2. **worker Lambda → Cloudflare AI Search 連携**
   - エンドポイント: `https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai-search/instances/line-manual-bot/search`
   - **リクエストは `{"messages": [{"role": "user", "content": "質問文"}]}` 形式**(OpenAI互換。単純な`query`ではない — env-setup-record §7)
   - トークン: SSM `/line-manual-bot/cloudflare/ai-search-token`(AI Search: 編集権限)
3. **Claude Haiku 4.5 での回答生成**
   - プロンプトには検索ヒットチャンクのみを入れる。ツールは一切与えない(F-01の物理的担保、§3.4 第0段)
   - APIキー: SSM `/line-manual-bot/anthropic/api-key`
   - LLMに生成させるのは**回答本文のみ**。出典はLLMに出力させない(下記4)
4. **出典表示(F-02)のフォールバック実装**(§3.4)
   - 出典は**コード側**で検索結果(ファイル名+チャンク本文)から組み立てる
   - チャンク本文の先頭付近にMarkdown見出し(`#`〜`###`)があれば「ファイル名 > 見出し」で提示
   - 見出しが取れなければファイル名のみ提示
5. **マニュアル(.docx)のR2アップロードと索引化確認**

## 実測タスク(P1の重要な目的)

- [ ] AI Search呼び出しのレイテンシを実測する
- [ ] 日本語検索精度を実測する。不足があれば以下の逃げ道を検討(§4):
  1. ハイブリッド検索(ベクトル+BM25)の有効化(現在オフ)
  2. AI Gateway経由で埋め込みモデルを差し替え(OpenAI等)
- [ ] 見出しメタデータの取得可否を確認し、F-02フォールバックの要否を確定する

## 関連する設計判断(抜粋)

- AI Searchのチャンク分割・埋め込みは「スマートデフォルト」のまま開始(env-setup-record §2.2)。精度実測の結果で見直す
- AI Search呼び出し失敗はエスカレーション扱いにフォールバック(誤情報より安全、§6)。ただしエスカレーションフロー自体はP2実装のため、**P1では定型エラーメッセージを返信した上で例外を投げ、SQSリトライ → DLQ隔離に載せる**(計画時に確定)
  - 理由: LINEの`replyToken`は短時間で失効するためリトライ経路では返信できず、ユーザーへの即時フィードバックを優先する。一方でDLQ・CloudWatchアラームによる障害検知の経路は残したい。設計書§3.7の最終形(通知してからDLQへ隔離)と同じ形であり、P2ではreplyをpushに差し替えるだけで済む
- 検索ヒットが0件だった場合は、定型メッセージ(マニュアルに該当する記載が見つからなかった旨)を返す。スコア閾値による足切り・エスカレーションはP2スコープ
- マニュアルのファイルサイズ上限は4MB。超過は索引されずエラーログに残るのみ(§6のリスク — 運用手順はP4)

## テスト

検索・LLMのポートをモックに差し替え、外部APIなしでロジックを検証する(実APIとの結合は上記「実測タスク」で担保)。

- [x] 出典フォールバックのユニットテスト: チャンク先頭に見出しあり→「ファイル名 > 見出し」/ 見出しなし→ファイル名のみ / 同一出典の重複排除
- [x] AI Searchレスポンスのパースのユニットテスト(正常応答・エラー応答・想定外の形)
- [x] 冪等化のユニットテスト: 同じ `webhookEventId` の2回目はスキップされる(P0の`webhookHandler.test.ts`で担保済み)
- [x] 回答生成プロンプトの組み立てテスト: 検索ヒットチャンク以外の情報が混入しないこと(F-01の担保)
- [x] worker全体の配線テスト(全ポートをモック): 正常系 / ヒット0件 / 検索失敗・生成失敗時に定型返信してから例外を投げること

## 完了条件

- [ ] マニュアルに載っている質問に、出典付きで正しく回答する(手動確認)
- [ ] レイテンシ・日本語検索精度の実測値が記録されている
- [ ] 見出しメタデータの取得可否が確認され、F-02フォールバックの要否が確定している

## スコープ外

- 未回答判定の二段構え・エスカレーション(→P2)。P1では検索スコアをログに残すところまで
- マルチターン・クエリ書き換え(→P3)
